PFAgent · IEEE 14 to 118-bus evaluation

Can a language model act as a power-flow analyst an operator can trust? This evaluation asks that of six ways to answer the same requests, from a deterministic parser to the solver-grounded agent, on the same four IEEE systems, with the same scoring.

The problem

An operator writes a request in plain English about an IEEE test system (14, 30, 57 or 118 buses): run the power flow, change a load, take a line out, scan every single outage. Somebody has to turn that sentence into the right solver operations with the right arguments, compute the result, and report the numbers the operator needs, in the units they expect. Today that somebody is an engineer with a power-flow tool. The question is what happens when it is a language model.

"Load the 14-bus test case (case14), set the active load at bus 4 to 42.7 MW, disconnect the line between bus 3 and bus 4, reconnect the line between bus 3 and bus 4, and finally rerun the power flow, then list every line whose loading is above 80%."

One of the 40 requests per system. Ten are plain, ten state a value or a criterion, ten chain several operations, ten are ambiguous on purpose (numbers spelled out, units in kW, 0-based indices).

What a correct answer needs

  • Formulation: the right operations, in order, with the arguments the request implies and nothing invented.
  • Numbers: voltages, flows, losses and violations of the resulting state, within tolerance of the solver's solution.
  • The operator's answer: the bus, the line, the ranking, or the list that was asked for.

What can go wrong

  • Plausible numbers that are not the solver's: wrong, presented as right.
  • A right-looking plan with a wrong argument: the wrong bus, a made-up MVAr value, an index off by one.
  • Answering a request that cannot be completed instead of saying so.

What we expect from PFAgent

Every reported number comes from PandaPower and passes a verification gate before it reaches the operator. When the gate cannot pass, the request is escalated to a person rather than answered. The target for the solver-grounded row: solved + escalated = 100%, wrong, unflagged = 0%.
